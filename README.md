# 운동 일지 (tlog) — Obsidian 플러그인

헬스장에서 세트마다 숫자 버튼 1탭으로 기록하는 Obsidian 플러그인. 무게와 횟수는 사용자가 정하고, 앱은 지난번 값을 미리 채워 두고
날짜별 기록과 주간·월간 최고 기록을 보여 줘서 점진적 과부하가 되고 있는지 한눈에 보이게 한다. 숫자를 제안하거나 강요하지 않는다.
기록은 볼트의 `tlog.md` 파일 하나에 텍스트로 쌓이고, Remotely Save가 Dropbox로 올려 PC에 도착한다.
설계 전체는 [PLAN.md](PLAN.md).

## 폰(아이폰) 설치 — 한 번만

1. Obsidian `training` 볼트에서 설정 → 커뮤니티 플러그인 → 제한 모드 끄기 → 탐색 → **BRAT** 설치·활성화.
2. 설정 → BRAT → **Add Beta plugin** → `https://github.com/sanghwa12/training-log-program` → Add.
3. 설정 → 커뮤니티 플러그인 → **운동 일지** 켜기. 이후 Obsidian을 열 때마다 기록 화면이 자동으로 뜬다.
4. (예비) 설정 → 모바일 → Quick Action 구성 → `운동 일지: 열기`. 아래로 당기기 한 번으로 열린다.
5. 갱신: BRAT 설정에서 "Check for updates" (또는 시작 시 자동 갱신 켜기).

## Remotely Save 설정(폰) — 한 번만

| 항목 | 값 |
|---|---|
| Run once on startup automatically | 1초 |
| Run automatically every N | 끔 |
| Sync on save | 끔 (이 뷰에서는 작동하지 않음) |
| Sync config dir | 끔 |
| **Protect modify percentage** | **100** (기본 50이면 파일 1~2개짜리 볼트에서 동기화가 매번 중단됨) |
| Enable mobile status bar | 켬 |

코어 설정 → 파일 복구: 스냅샷 간격 1분, 보관 7일 이상.

## 사용법

**홈**: 오늘 날짜, 다음 템플릿(A/B 교대), 종목별 "지난번 9/2: 60×8 60×8 60×7". 큰 버튼 "A 시작하기" 하나. 그 아래 작은 글자로 "A 말고 B 하기", "동기화".

**기록 화면** (종목 하나씩):

```
9/8 (화) · A 18:32
스쿼트                                   1/3
지난번 9/2: 60×8  60×8  60×7
60 kg로 3세션 연속 (8/18부터)              ← 사실만 알려 주는 힌트
무게   [−]     60 kg     [+]
횟수   [−]      8회      [+]
[        기록   60 kg × 8회        ]      ← 이것만 누르면 한 세트 저장
오늘 2세트: [60×8] [60×8]               ← 세트를 누르면 고치거나 지운다
[ ‹ 이전 ]      [ 다음: 벤치 › ]
더보기 ⋯
```

- 무게·횟수는 지난번 값이 미리 채워진다. 그대로면 "기록"만 누른다. 바꾸려면 −/+(길게 누르면 빠르게) 또는 **숫자를 눌러 직접 입력**.
- 세트 수는 정해져 있지 않다. 하고 싶은 만큼 기록하고 "다음: 벤치 ›"로 넘어간다.
- **오늘 기록 수정·삭제**: "오늘 n세트" 줄의 세트를 누르면 그 값이 무게·횟수 칸에 올라오고 큰 버튼이 "2세트 수정"으로 바뀐다. 값을 고쳐 누르면 교체, 아래 "2세트 삭제"를 누르면 삭제, "취소"로 돌아간다. 세션을 끝낸 뒤에도 홈에서 종목을 누르면 그 종목으로 바로 들어가 고칠 수 있다.
- 마지막 종목에서는 "다음" 자리가 "세션 끝내기 ✓"가 된다. 누르면 홈으로 가고 동기화가 실행된다.
- **더보기 ⋯** 안에 가끔 쓰는 것: **기록 보기**(날짜별 기록·주간 최고·월간 최고), **종목 추가**(저장된 종목에서 고르거나 새 이름 입력. 숨긴 종목 복원도 여기), **세션 끝내기**(중간에 끝낼 때), **종목 삭제**(두 번 눌러 확정. 지난 기록이 있으면 지우지 않고 숨긴다).

## 최초 설정 순서

1. 폰에서 플러그인을 켜고 첫 세트를 기록한다 → `tlog.md`가 볼트에 생긴다(기본 종목 6개).
2. "세션 끝내기" 또는 홈의 "동기화"를 눌러 Dropbox에 올린다. PC의 `C:\Users\USER\Dropbox\앱\remotely-save\training\tlog.md`에 도착한다.
3. 종목은 앱의 "종목 추가"에서 바로 만들고 "이 종목 삭제"로 지운다. 템플릿(A/B)을 바꾸려면 PC에서 `%% ex %%` 줄을 고친다(아래 문법). 저장 후 `npm run check`.
4. 폰에서 Obsidian을 한 번 열면 시작 시 동기화로 내려온다.

## tlog.md 문법

```
%% tlog v3 2026-09-08T18:32:10+09:00 %%
%% ex squat A 스쿼트 %%
%% ex 레그_프레스 A 레그 프레스 %%
2026-09-08 session A 18:32
2026-09-08 squat 60x8 60x8 60x8
2026-09-08 레그_프레스 80x12 80x12
```

- 첫 줄은 플러그인이 쓰는 헤더(마지막 기록 시각). 손대지 않는다.
- `%% ex id 템플릿 이름 %%`. `id`는 공백·`%`만 없으면 되고(한글 가능; 앱에서 만든 종목은 이름의 공백을 `_`로 바꾼 것), 한 번 정하면 바꾸지 않는다. 이름은 공백 포함 가능. 템플릿이 `-`면 숨긴 종목.
- 세션 줄: `날짜 session 템플릿 시작시각`. 시각은 첫 세트를 찍은 시각(HH:MM)이며 없어도 된다. 날짜 블록은 오름차순, 하루 1세션.
- 기록 줄: `날짜 id 무게x횟수 ...`. 세트 수는 찍은 만큼이다. 맨몸 종목은 무게 0.
- Obsidian 읽기 모드에서는 `%%` 줄이 숨겨지고 기록만 보인다. 예전 v1·v2 파일도 읽히며 다음 저장 때 v3로 바뀐다.

## 점진적 과부하를 보는 방법

앱은 무게를 정해 주지 않는다. 대신 다음을 보여 준다.

- 종목마다 지난번 기록(날짜 포함)과 미리 채워진 지난번 무게·횟수.
- 힌트: 마지막 운동 후 14일 이상 지났을 때, 같은 최고 무게가 3세션 이상 이어질 때, 직전 두 세션의 최고 무게가 다를 때. 모두 사실만 말한다.
- "기록 보기": 날짜별 기록, 주간 최고(월~일), 월간 최고. 여기서 주·월 단위로 조금씩 올라가는지 확인하고, 올릴 때를 스스로 정한다.

다음 세션은 직전 세션의 반대 템플릿(A→B→A). 요일은 보지 않는다.

## PC에서 손으로 고칠 때의 규칙

1. 세션 중이 아닐 때.
2. 폰에서 동기화 성공을 본 뒤(세션 끝 알림, 또는 집에서 Obsidian을 한 번 연 뒤).
3. 파일 이름·위치는 바꾸지 않고 내용만.
4. 헤더 줄은 손대지 않고 문법을 지켜서. 저장 후 `npm run check`.
5. 그 다음 폰에서 Obsidian을 한 번 열어 받는다.

Remotely Save는 병합 없이 수정 시각이 늦은 쪽으로 덮어쓴다. 규칙을 어기면 폰 홈에 "덮어씀" 빨간 띠가 뜨고 쓰기가 잠긴다. 되돌리기는 Obsidian 설정 → 파일 복구, 또는 Dropbox 웹의 버전 기록.

## PC에서 읽기

```python
import pandas as pd
df = pd.read_csv(r"C:\Users\USER\Dropbox\앱\remotely-save\training\tlog.md", sep=r"\s+", engine="python",
                 comment="%", header=None, names=["date","id","s1","s2","s3","s4","s5","s6"], encoding="utf-8")
df = df[df.id != "session"]   # s1..s6은 "kgxreps" 문자열
```

세트가 6개를 넘으면 `names`를 늘린다. 파일 검사: `npm run check` (경로를 인자로 주면 다른 파일).

## 제약

하루 1세션 · 종목당 세션에 작업 무게 1개(가벼운 세트는 워밍업으로 무시) · `id` 불변 · 과거 세션 편집은 PC에서 파일로.

## 개발

```
npm install
npm test          # 규칙 엔진·파서 (node --test)
npm run typecheck
npm run dev       # tlog-vault\.obsidian\plugins\tlog\ 에 빌드 + 감시
npm run build     # 저장소 루트 main.js (Release 자산)
```

PC Obsidian에서 `C:\Users\USER\dev\training-log-program\tlog-vault`를 볼트로 열고 커뮤니티 플러그인에서 `운동 일지`를 켠다.
소스를 고치면 명령 팔레트 "Reload app without saving".

## 배포 (BRAT용 Release)

1. `manifest.json`의 `version`을 올리고 커밋·푸시.
2. `git tag <version>` (예: `0.1.1`, `v` 없이) → `git push origin <version>`.
3. GitHub Actions(`.github/workflows/release.yml`)가 테스트·빌드 후 Release를 만들고 `main.js`, `manifest.json`, `styles.css`를 자동으로 첨부한다. 태그와 manifest version이 다르면 실패한다.
4. 폰 BRAT에서 Check for updates.

수동으로 할 때는 `npm run build`로 만든 세 파일을 GitHub 웹의 Release에 직접 첨부한다.

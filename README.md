# 운동 일지 (tlog) — Obsidian 플러그인

헬스장에서 세트마다 숫자 버튼 1탭으로 기록하는 Obsidian 플러그인. 무게와 횟수는 사용자가 정하고, 앱은 지난번 값을 미리 채워 두고
세션 총량(세트마다 kg×횟수의 합)과 주간·월간 최고 총량을 보여 줘서 점진적 과부하가 되고 있는지 한눈에 보이게 한다. 숫자를 제안하거나 강요하지 않는다.
기록은 볼트의 `tlog.md` 파일 하나에 텍스트로 쌓이고, Remotely Save가 Dropbox로 올려 PC에 도착한다.
설계 전체는 [PLAN.md](PLAN.md).

## 폰(아이폰) 설치 — 한 번만

1. Obsidian `training` 볼트에서 설정 → 커뮤니티 플러그인 → 제한 모드 끄기 → 탐색 → **BRAT** 설치·활성화.
2. 설정 → BRAT → **Add Beta plugin** → `https://github.com/sanghwa12/training-log-program` → Add.
3. 설정 → 커뮤니티 플러그인 → **운동 일지** 켜기. 이후 Obsidian을 열 때마다 기록 화면이 자동으로 뜬다.
4. (예비) 설정 → 모바일 → Quick Action 구성 → `운동 일지: 열기`. 아래로 당기기 한 번으로 열린다.
5. 갱신: BRAT 설정에서 "Check for updates" (또는 시작 시 자동 갱신 켜기).

## Remotely Save 설정(폰) — 한 번만

| 항목 | 값 |
|---|---|
| Run once on startup automatically | 1초 |
| Run automatically every N | 끔 |
| Sync on save | 끔 (이 뷰에서는 작동하지 않음) |
| Sync config dir | 끔 |
| **Protect modify percentage** | **100** (기본 50이면 파일 1~2개짜리 볼트에서 동기화가 매번 중단됨) |
| Enable mobile status bar | 켬 |

코어 설정 → 파일 복구: 스냅샷 간격 1분, 보관 7일 이상.

## 사용법

**홈**: 오늘 날짜와 종목 전체 목록(파일 순서). A/B 같은 구분은 없고 오늘 할 종목을 그때그때 고른다. 종목마다 "오늘: 60×8 60×8" 또는 "지난번 9/2: 60×8 60×8 60×7"이 보이고, **종목을 누르면 기록 화면**이 열린다. 아래 작은 글자로 "+ 종목 추가", "숨긴 종목", "동기화".

**기록 화면** (종목 하나씩):

```
9/8 (화) · 18:32 시작
스쿼트                                   1/6
지난번 9/2: 60×8  60×8  60×7 = 1,380 kg
추천 60 kg × 8회                           ← 지난 기록으로 계산한 추천(정보)
모든 세트 8회까지 · 전부 12회가 되면 한 칸 올림
직전 총량 1,380 kg, 그 전 1,320 kg (+60 kg)   ← 사실만 알려 주는 힌트
무게   [−]     60 kg     [+]
횟수   [−]      8회      [+]
[        기록   60 kg × 8회        ]      ← 이것만 누르면 한 세트 저장
오늘 2세트: [60×8] [60×8] = 960 kg       ← 세트를 누르면 고치거나 지운다
[ ‹ 목록 ]      [ 다음: 벤치 › ]
더보기 ⋯
```

**점진적 과부하는 총량으로 본다.** 총량 = 세트마다 무게×횟수를 더한 값. 무게를 올리든, 횟수를 늘리든, 세트를 하나 더 하든 총량이 올라간다. 세트 목록 끝의 "= 960 kg", 힌트, 기록 보기의 주간·월간 최고가 모두 이 수치다.

**추천 중량·횟수.** 기록 화면의 "지난번" 줄 아래에 한 줄로 보인다. 미리 채워지는 값은 그대로 지난번 기록이고, 추천을 따를지는 직접 정한다. 규칙은 해 오던 방식(같은 중량에서 반복 늘리기)에 상한을 둔 것이다.
- 상한 = 그 종목 첫 기록의 최고 반복, 12회보다 작으면 12회. 레터럴처럼 20회로 시작했으면 20회.
- 직전 세션의 작업 세트(그날 최고 무게로 한 세트)가 모두 상한 이상이면 **한 칸 올림**. 반복은 세트 총량이 줄지 않을 만큼(무게 비율로 내림). 예: 35 kg 13회 → 37.5 kg 12회.
- 아니면 **같은 무게, 가장 적었던 세트 +1회**. 예: 30 kg 12·12·12·11 → 30 kg 12회.
- 한 칸 = 그 종목의 **무게 칸**. 기계마다 다르므로 종목별로 더보기 → "무게 칸"에서 1 · 2 · 2.5 · 5 kg 중 하나를 한 번 골라 둔다. 고르지 않으면 2.5 kg. 고른 칸은 추천과 무게 −/+ 버튼이 같이 쓴다(5 kg 기계는 + 한 번에 5 kg).
- 맨몸 종목은 직전 총 반복 +1회. 지난 날짜를 고칠 때는 보이지 않는다.

**맨몸 종목은 무게 0.** 무게를 0으로 내리면 "맨몸"으로 보이고, 세트는 "8회"처럼, 합계는 총량 대신 **총 반복**("= 18회")으로 나온다. 기준은 그 종목의 가장 최근 세션이다: 마지막 세션이 모두 0 kg이면 힌트·기록 보기도 총 반복으로 비교한다(예전에 다른 무게로 적은 기록도 반복 수끼리 비교).

- 무게·횟수는 지난번 값이 미리 채워진다. 그대로면 "기록"만 누른다. 바꾸려면 −/+(길게 누르면 빠르게) 또는 **숫자를 눌러 직접 입력**.
- 세트 수는 정해져 있지 않다. 하고 싶은 만큼 기록하고 "다음: 벤치 ›"(목록 순서상 다음 종목)나 "‹ 목록"으로 다른 종목을 고른다.
- **오늘 기록 수정·삭제**: "오늘 n세트" 줄의 세트를 누르면 그 값이 무게·횟수 칸에 올라오고 큰 버튼이 "2세트 수정"으로 바뀐다. 값을 고쳐 누르면 교체, 아래 "2세트 삭제"를 누르면 삭제, "취소"로 돌아간다. 나중에 홈에서 종목을 누르면 다시 들어가 고칠 수 있다.
- **지난 날짜 기록 수정**: 더보기 → **지난 기록 고치기** → 날짜를 누르면 같은 기록 화면이 그 날짜 모드가 된다(위에 "9/16 (수) 기록 고치는 중" 띠). 거기서 "기록"으로 빠뜨린 세트를 추가하거나 세트를 눌러 고치고 지우면 **모두 그 날짜로 저장**된다(오늘 날짜가 아니라). 그날 안 한 종목도 추가할 수 있다. "다음 ›"로 같은 날짜의 다른 종목으로 넘어가고, "오늘로 돌아가기"·"‹ 목록"·앱을 벗어나면 오늘 모드로 돌아온다.
- **종목 이름 바꾸기**: 더보기 → **이름 바꾸기** → 저장. 파일의 id(기록 줄의 열쇠)는 그대로 두고 보이는 이름만 바꾼다.
- 앱을 다시 열면 오늘 마지막으로 찍던 종목의 기록 화면으로 바로 돌아온다. "‹ 목록"을 눌렀으면 그날은 홈에 머문다.
- **동기화**: 앱을 벗어나거나 돌아올 때 미동기화 기록이 있으면 자동으로 올린다. 바로 올리고 싶으면 홈이나 더보기의 "동기화".
- **더보기 ⋯** 안에 가끔 쓰는 것: **기록 보기**(날짜별 기록과 총량·주간 최고 총량·월간 최고 총량), **지난 기록 고치기**, **이름 바꾸기**, **무게 칸**(이 기계가 몇 kg씩 올라가는지, 누르면 바로 저장), **동기화**, **종목 삭제**(두 번 눌러 확정. 지난 기록이 있으면 지우지 않고 숨긴다. 홈의 "숨긴 종목"에서 복원).

## 최초 설정 순서

1. 폰에서 플러그인을 켜고 첫 세트를 기록한다 → `tlog.md`가 볼트에 생긴다(기본 종목 6개).
2. "세션 끝내기" 또는 홈의 "동기화"를 눌러 Dropbox에 올린다. PC의 `C:\Users\USER\Dropbox\앱\remotely-save\training\tlog.md`에 도착한다.
3. 종목은 홈의 "+ 종목 추가"로 만들고, 기록 화면의 더보기 → 삭제로 지운다. 홈에 보이는 순서를 바꾸려면 PC에서 `%% ex %%` 줄의 순서를 바꾼다(아래 문법). 저장 후 `npm run check`.
4. 폰에서 Obsidian을 한 번 열면 시작 시 동기화로 내려온다.

## tlog.md 문법

```
%% tlog v4 2026-09-08T18:32:10+09:00 %%
%% ex squat 스쿼트 %%
%% step squat 5 %%
%% ex 레그_프레스 레그 프레스 %%
%% hidden row 바벨로우 %%
2026-09-08 session 18:32
2026-09-08 squat 60x8 60x8 60x8
2026-09-08 레그_프레스 80x12 80x12
```

- 첫 줄은 플러그인이 쓰는 헤더(마지막 기록 시각). 손대지 않는다.
- `%% ex id 이름 %%`가 종목 하나. 줄 순서가 홈의 순서다. `id`는 공백·`%`만 없으면 되고(한글 가능; 앱에서 만든 종목은 이름의 공백을 `_`로 바꾼 것), 한 번 정하면 바꾸지 않는다. 이름은 공백 포함 가능. `ex` 대신 `hidden`이면 숨긴 종목(기록은 유지, 목록에서만 제외).
- `%% step id kg %%`는 그 종목의 무게 칸(선택). 종목 줄 바로 뒤에 온다. 없으면 2.5 kg. 앱의 더보기 → 무게 칸에서 정하면 플러그인이 쓴다. 0.3.x 이하 버전은 이 줄을 무시한다.
- 세션 줄: `날짜 session 시작시각`. 시각은 첫 세트를 찍은 시각(HH:MM)이며 없어도 된다. 날짜 블록은 오름차순, 하루 1세션.
- 기록 줄: `날짜 id 무게x횟수 ...`. 세트 수는 찍은 만큼이다. 맨몸 종목은 무게 0.
- Obsidian 읽기 모드에서는 `%%` 줄이 숨겨지고 기록만 보인다. 예전 v1~v3 파일도 읽히며 다음 저장 때 v4로 바뀐다(옛 A/B 템플릿 표시는 버려진다).

## 점진적 과부하를 보는 방법

앱은 무게를 정해 주지 않는다. 대신 다음을 보여 준다.

- 종목마다 지난번 기록(날짜 포함)과 미리 채워진 지난번 무게·횟수.
- 힌트: 마지막 운동 후 14일 이상 지났을 때, 같은 총량이 3세션 이상 이어질 때, 직전 두 세션의 총량이 다를 때(변화량). 맨몸 종목은 총 반복으로. 모두 사실만 말한다.
- "기록 보기": 날짜별 기록(= 총량), 주간 최고 총량(월~일), 월간 최고 총량. 여기서 주·월 단위로 조금씩 올라가는지 확인하고, 올릴 때를 스스로 정한다.

어떤 종목을 언제 할지도 앱이 정하지 않는다. 홈 목록에서 그날 할 종목을 고른다.

## PC에서 손으로 고칠 때의 규칙

1. 세션 중이 아닐 때.
2. 폰에서 동기화 성공을 본 뒤(세션 끝 알림, 또는 집에서 Obsidian을 한 번 연 뒤).
3. 파일 이름·위치는 바꾸지 않고 내용만.
4. 헤더 줄은 손대지 않고 문법을 지켜서. 저장 후 `npm run check`.
5. 그 다음 폰에서 Obsidian을 한 번 열어 받는다.

Remotely Save는 병합 없이 수정 시각이 늦은 쪽으로 덮어쓴다. 규칙을 어기면 폰 홈에 "덮어씀" 빨간 띠가 뜨고 쓰기가 잠긴다. 되돌리기는 Obsidian 설정 → 파일 복구, 또는 Dropbox 웹의 버전 기록.

import pandas as pd
df = pd.read_csv(r"C:\Users\USER\Dropbox\앱\remotely-save\training\tlog.md", sep=r"\s+", engine="python",
                 comment="%", header=None, names=["date","id","s1","s2","s3","s4","s5","s6"], encoding="utf-8")
df = df[df.id != "session"]   # s1..s6은 "kgxreps" 문자열
```

세트가 6개를 넘으면 `names`를 늘린다. 파일 검사: `npm run check` (경로를 인자로 주면 다른 파일).

```

소스를 고치면 명령 팔레트 "Reload app without saving".

## 배포 (BRAT용 Release)

1. `manifest.json`의 `version`을 올리고 커밋·푸시.
2. `git tag <version>` (예: `0.1.1`, `v` 없이) → `git push origin <version>`.
3. GitHub Actions(`.github/workflows/release.yml`)가 테스트·빌드 후 Release를 만들고 `main.js`, `manifest.json`, `styles.css`를 자동으로 첨부한다. 태그와 manifest version이 다르면 실패한다.
4. 폰 BRAT에서 Check for updates.

수동으로 할 때는 `npm run build`로 만든 세 파일을 GitHub 웹의 Release에 직접 첨부한다.
